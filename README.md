# 修仙 · 凡界

TypeScript 编写的修仙增量游戏初版试玩，面向 Windows 11。当前包含战斗、背包、功法、洞府、境界与说明六个页面。

界面采用用户确认的 ChatGPT 深色方向：深灰主区、较深侧栏、浅色文字和按钮。战斗页并排显示角色与敌怪信息，最近记录默认收起，点击“展开”可查看完整记录。

战斗展示区左侧为2D修仙角色，右侧为测试用小灰狼；怪物血条位于灰狼头顶，手动与自动攻击会实时更新。小灰狼仅作为临时外观，正式怪物名称仍为 `[待编辑]`，没有新增狼类怪物配置或攻击规则。

左侧“背包”打开角色背包，用小格子展示物品。初始背包为空，角色数据已预留物品列表。当前空格只是展示区域，不代表容量上限；物品增加后会继续显示更多格子。掉落物、容量、堆叠、使用和整理规则仍待确认，当前刷怪不会生成背包物品。

## Windows 11 直接打开

完整解压交付的 `修仙初版.zip`，双击文件夹里的 `index.html`，使用 Edge 或 Chrome 打开。保留全部文件，尤其是 `game.js`、`game.css`、`icons` 与 `actors` 文件夹。

构建产物不依赖 Node.js、网络、账号或在线服务。本轮交付为浏览器运行的本地版本；尚未封装为 exe。

## 当前可操作内容

- 切换战斗、背包、功法、洞府、境界与说明页面。
- 查看格子形式的角色背包，初始没有物品；查看背包时自动攻击继续进行。
- 点击敌怪立绘（当前为测试小灰狼）或“攻击”按钮进行攻击，也可以开启自动攻击。
- 击败普通怪获得修为，达到门槛后点击突破小阶段。
- 默认只显示一条最近记录；展开后查看本次战斗最近八条记录。
- 展开七大境界，查看全部 33 个阶段的角色属性、普通怪/首领生命，以及 32 次突破的修为需求。
- 查看已确认设定，以及尚待确定的内容。

**当前已能刷取初始普通怪并突破小阶段。** 初始角色为炼气一层，生命100、攻击10、防御2、自动攻速1次/秒、回血1点/秒，修为0/100。敌怪名字统一为 `[待编辑]`。

怪物生命现已配置：普通怪初始60、首领300，按照怪物自身实力使用已批准的成长倍率。按用户要求，怪物攻击暂不配置；没有设置默认攻击数值或反击逻辑。

当前开放固定为炼气一层实力的普通怪：生命60、击杀奖励10修为，击败后刷新相同配置。每次伤害直接使用角色攻击值；玩家升级后旧怪的生命和奖励保持不变。手动点击一次触发一击，自动攻击按角色攻速执行，开启自动后仍可点击攻击。切换游戏页面保留本次战斗并继续自动攻击。

成功突破扣除门槛、保留溢出修为。当前可玩进度停在炼气九层，大境界闭关的时长、概率与失败损失仍待确认。具体区域和首领清怪门槛、功法掉落与装配、洞府收益等内容继续留空。

当前尚未接入存档：刷新或重新打开页面会从初始状态开始，不结算关闭期间收益。

## 开发与构建

安装 Node.js 22.18 或以上版本，在项目目录执行：

```bash
npm install
npm run dev
```

Vite 会打印本地开发地址，默认端口为 5173。也可以在 Windows 双击 `启动开发.cmd`，自动打开浏览器。

```bash
npm test
npm run build
```

构建后直接打开 `dist/index.html` 即可。编译输出使用 IIFE 脚本，不通过 fetch 加载数据，不依赖浏览器对 `file://` 的模块支持。

## 代码结构

```text
src/
  main.ts                 页面、导航和界面交互
  style.css               响应式界面
  game/
    realms.ts             已确认境界与阶段顺序
    balance.ts            角色属性、怪物生命、成长倍率与修为需求
    progression.ts        成功扣除修为与溢出保留
    combat.ts             普通怪生成、单次攻击、击杀奖励与刷新
    model.ts              玩家、基础物品容器、区域和闭关数据类型
    rules.ts              已确认规则的独立计算函数
    content.ts            正式内容配置、已确认与待确认记录
public/icons/              本地 Microsoft Fluent 图标及 MIT 许可
public/actors/             角色与测试小灰狼的透明背景2D立绘
tests/rules.test.ts        核心规则验证
tests/browser.mjs          浏览器与离线产物验证
scripts/build.mjs         可直接双击运行的产物生成
docs/framework.md         设计记录与范围边界
```

规则函数只接收明确传入的数值。未编写防御伤害公式、功法类别、技能消耗/冷却、掉落算法、洞府升级条件等待定机制。闭关时长、成功率与失败扣除量保持待确认。测试中的隔离样例不作为游戏默认数据。

浏览器验证使用已安装的 Chromium：`npm run test:browser`。测试路径可按其他开发环境的浏览器安装位置调整；它不是运行游戏所需的依赖。也可以传入静态服务地址，例如 `npm run test:browser -- http://127.0.0.1:4173/`。

验证包含 TypeScript/生产构建、核心规则与数值增长、攻击/奖励防重复结算，以及 Chromium 的背包入口与空格子、查看背包期间的战斗状态、角色与灰狼左右位置、头顶血条、手动/自动攻击、击杀刷新、小阶段突破、记录展开、焦点保留、首屏操作与八种窗口宽度。当前环境策略禁止浏览器访问 `file://`，界面验证通过本地静态服务完成，尚未在 Windows 11 实机验证双击打开。

后续新增玩法、数值或变更规则，均先征求你的意见。
