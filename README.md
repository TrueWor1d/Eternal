# 修仙 · 凡界 v0.1.6

TypeScript 编写的修仙增量游戏初版试玩，面向 Windows 11。当前包含战斗、背包、功法、洞府、境界与说明六个页面。

界面沿用用户确认的 ChatGPT 深色方向：深灰主区、较深侧栏与暖白文字；玉青色强调当前导航、修为进度、当前境界与可突破状态。标题28px、正文14至16px，角色属性减少逐行分隔线，按钮统一圆角与150ms悬停过渡。战斗页并排显示角色与敌怪信息，最近记录默认收起，点击“展开”可查看完整记录。

战斗展示区左侧为已选定的简约像素修真者：白灰道袍、束发、空手，朝右站立。主角使用透明PNG，战斗页与背包装备区共用同一素材，战斗页显示尺寸略微放大。右侧测试小灰狼已统一为像素风；两者按像素方式显示。怪物血条位于灰狼头顶，自动攻击会实时更新。受击时灰狼轻微闪白180ms，并显示650ms伤害浮字；支持系统“减少动态效果”，开启时不闪白、不显示浮字、取消控件过渡。动效仅展示已结算伤害，不参与战斗计时或掉落随机数。小灰狼仅作为临时外观，正式怪物名称仍为 `[待编辑]`，没有新增狼类怪物配置或攻击规则。

点击左侧“背包”后，页面左边为人物装备，右边为角色背包格子。像素主角位于装备区中央，两侧自上而下对称排列四排：头盔／胸甲、左护腕／右护腕、主武器／副武器、左靴／右靴，共8个槽，当前均显示“未装备”，尚未开放装备资料、属性、掉落或穿戴操作。较窄窗口下，装备与背包按上下排列。初始背包为空；每次击败当前普通怪，有20%概率掉落测试物品“铜钱”，成功时等概率获得2至5个。铜钱自动存入同一个格子并累加数量，查看背包期间的自动战斗掉落也会即时更新。背包采用紧凑分页，每页24格，桌面格子约56px、间距8px；末页填满时自动增加空白下一页，也可以提前主动翻到下一页。格子正下方居中排列“上一页、页码、下一页”，首次打开时只有一页。已打开页数和当前页在本次游戏导航中保留，不设定总容量上限。掉落不会强制切换当前页，铜钱仍在原来的一格堆叠。其他掉落物、容量、物品使用和整理规则仍待确认。

## Windows 11 直接打开

完整解压交付的 `修仙初版-v0.1.6.zip`，双击文件夹里的 `index.html`，使用 Edge 或 Chrome 打开。保留全部文件，尤其是 `game.js`、`game.css`、`icons` 与 `actors` 文件夹。源码另见 `修仙初版源码-v0.1.6.zip`，后续每次修改交付递增一次版本号。

构建产物不依赖 Node.js、网络、账号或在线服务。本轮交付为浏览器运行的本地版本；尚未封装为 exe。

## 当前可操作内容

- 切换战斗、背包、功法、洞府、境界与说明页面。
- 查看中央像素主角及两侧对称排列的8个人物装备空槽、右侧角色背包格子与铜钱数量；查看背包时自动攻击继续进行，掉落即时入包。
- 在格子下方使用上一页、下一页切换背包，每页固定24格；未满也可进入空白下一页。
- 装备槽显示对应部位图标，铜钱显示图标与堆叠数量；图标仅用于辨识，不增加穿戴或使用操作。
- 打开游戏后自动战斗；空手每秒攻击一次，初始每次造成10点伤害。
- 击败普通怪获得修为，达到门槛后点击突破小阶段。
- 每次击杀独立判定20%概率掉落2至5个铜钱，同格堆叠；未触发掉落时不增加物品。
- 默认只显示一条最近记录；展开后查看本次战斗最近八条记录。
- 展开七大境界，查看全部 33 个阶段的角色属性、普通怪/首领生命，以及 32 次突破的修为需求。
- 查看已确认设定，以及尚待确定的内容。

**当前已能刷取初始普通怪并突破小阶段。** 初始角色为炼气一层，生命100、攻击10、防御2、自动攻速1次/秒、回血1点/秒，修为0/100。敌怪名字统一为 `[待编辑]`。

怪物生命现已配置：普通怪初始60、首领300，按照怪物自身实力使用已批准的成长倍率。按用户要求，怪物攻击暂不配置；没有设置默认攻击数值或反击逻辑。

当前开放固定为炼气一层实力的普通怪：生命60、击杀奖励10修为，击败后刷新相同配置。每次伤害直接使用角色攻击值；玩家升级后旧怪的生命和奖励保持不变。战斗采用纯自动攻击，不再提供手动攻击按钮或自动攻击开关，点击立绘也不会攻击。空手攻速固定为每秒一次，单次伤害沿用角色攻击值并保留原来的成长。切换页面、突破和刷新怪物都会继续自动战斗；导航与突破不会重置攻击计时。装备资料、穿戴规则及武器对属性的影响待后续确认。

成功突破扣除门槛、保留溢出修为。当前可玩进度停在炼气九层，大境界闭关的时长、概率与失败损失仍待确认。具体区域和首领清怪门槛、功法掉落与装配、洞府收益等内容继续留空。

当前尚未接入存档：刷新或重新打开页面会从初始状态开始，背包内铜钱也会重置，不结算关闭期间收益。

## 开发与构建

安装 Node.js 22.18 或以上版本，在项目目录执行：

```bash
npm install
npm run dev
```

Vite 会打印本地开发地址，默认端口为 5173。也可以在 Windows 双击 `启动开发.cmd`，自动打开浏览器。

```bash
npm test
npm run build
```

构建后直接打开 `dist/index.html` 即可。编译输出使用 IIFE 脚本，不通过 fetch 加载数据，不依赖浏览器对 `file://` 的模块支持。

## 代码结构

```text
src/
  main.ts                 页面、导航、8个装备空槽和界面交互
  style.css               响应式界面
  game/
    realms.ts             已确认境界与阶段顺序
    balance.ts            角色属性、怪物生命、成长倍率与修为需求
    progression.ts        成功扣除修为与溢出保留
    combat.ts             普通怪生成、单次攻击、击杀奖励与刷新
    loot.ts               铜钱20%掉落、随机数量与同格堆叠
    inventory.ts          每页24格、满页扩展与手动页码切片
    model.ts              玩家、基础物品容器、区域和闭关数据类型
    rules.ts              已确认规则的独立计算函数
    content.ts            正式内容配置、已确认与待确认记录
public/icons/              本地 Microsoft Fluent 界面图标及 MIT 许可
public/icons/gear/         Game Icons 装备、铜钱图标及 CC BY 3.0 署名许可
public/actors/             共用的像素主角与像素测试小灰狼透明PNG
tests/rules.test.ts        核心规则验证
tests/loot.test.ts         掉率与数量边界、堆叠和击杀结算验证
tests/inventory.test.ts    分页边界、空白页及跨页物品完整性验证
tests/browser.mjs          浏览器与离线产物验证
scripts/build.mjs         可直接双击运行的产物生成
docs/framework.md         设计记录与范围边界
```

规则函数只接收明确传入的数值。未编写防御伤害公式、功法类别、技能消耗/冷却、其他物品掉落、铜钱用途、洞府升级条件等待定机制。闭关时长、成功率与失败扣除量保持待确认。测试中的隔离样例不作为游戏默认数据。

浏览器验证使用已安装的 Chromium：构建后执行 `npm run test:browser`，脚本自动启动仅供本机使用的临时静态服务，完成后关闭。浏览器路径可按其他开发环境调整；它不是运行游戏所需的依赖。也可以传入已有静态服务地址，例如 `npm run test:browser -- http://127.0.0.1:4173/`。

v0.1.6已通过 TypeScript/生产构建和35项逻辑测试。本次仅调整界面与表现层，`src/game`下的全部规则文件与v0.1.5源码逐字节一致，主角PNG保持原素材。测试包含分页与堆叠、各阶段空手攻速固定为1、原伤害成长、20%概率边界、2至5的数量边界、连续击杀与死亡后重复攻击不再结算。
